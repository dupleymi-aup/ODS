ODS устанавливает и связывает между собой всё, что нужно для локальной работы с ИИ, — так что вам не придётся вручную собирать Ollama, Open WebUI, n8n, ComfyUI и инструменты приватности:

- **Локальный запуск моделей** — выполняйте открытые модели на своём оборудовании
- **Веб-интерфейс в стиле ChatGPT** — общайтесь с моделями из любого браузера
- **Панель управления** — управляйте моделями, сервисами, настройкой, состоянием GPU и расширениями из одного места
- **Голос, агенты и рабочие процессы** — создавайте автоматизации, которые умеют слушать, говорить, вызывать инструменты и выполнять работу
- **RAG и поиск** — подключайте локальные документы, приватный поиск и процессы извлечения данных
- **Генерация изображений** — запускайте локальные инструменты генерации, не отправляя промпты в облачные API
- **Приватность и эксплуатация** — держите аутентификацию сервисов, секреты, наблюдаемость и диагностику в одном локальном стеке

Без облака. Без подписок. Инференс, история чатов и ваши файлы остаются на вашей машине, и ODS не собирает телеметрию. По умолчанию выход в сеть выполняется только для загрузки моделей и образов контейнеров, проверки GitHub на предмет релизов ODS и веб-поиска, который агент Portal выполняет по вашему запросу; [FAQ](ods/FAQ.md#is-my-data-private) разбирает каждый случай и объясняет, как их отключить. Облачный и гибридный API-режимы доступны по желанию.

> **Статус: предрелиз V3.** Установщики ниже ставят текущую ветку `main`, в которую непрерывно вносятся исправления и которая не является подписанным релизом; [предпросмотр верифицированного установщика](ods/docs/VERIFIED_INSTALL_PREVIEW.md) остаётся отдельным, пока подписанный релиз не пройдёт сквозное тестирование. Существующие установки получают исправления кода повторным запуском установщика ([как это сделать](ods/SECURITY.md#updating-an-existing-installation)); команда `ods update` обновляет только образы контейнеров. `v3.0.0` — последний опубликованный исходный релиз; перед его фиксацией проверьте [рекомендации по безопасности](https://github.com/Osmantic/ODS/security/advisories). Известные ограничения и статус валидации: [примечания к релизу V3](ods/docs/RELEASE_NOTES_3.0.0.md), [Валидация релиза](ods/docs/RELEASE_VALIDATION.md), [Каналы релизов](ods/docs/RELEASE_CHANNELS.md) и [Доверие к установщику](ods/docs/INSTALLER_TRUST.md).

В корне репозитория находятся этот README, установщики, политика безопасности и CI-воркфлоу; `ods/` — это сам продукт: сервисы, фазы установщика, compose-файлы, панель управления, CLI, тесты и документация оператора.

## Начало работы

Выберите свою систему, скопируйте блок и выполните его в обычном терминале. ODS установит стек, подберёт модель под ваше оборудование, запустит сервисы и даст вам локальный веб-интерфейс.

**Linux или macOS**

```bash
curl -fsSL https://install.osmantic.com/ods.sh | bash
```

**Windows PowerShell** — интерактивная настройка Ubuntu/WSL2 с Pixel/Portal

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $ProgressPreference = 'SilentlyContinue'
    $odsSrc = Join-Path $env:TEMP ('ods-install-' + [guid]::NewGuid().ToString('N'))
    $odsZip = Join-Path $odsSrc 'ods-main.zip'
    New-Item -ItemType Directory -Path $odsSrc | Out-Null
    Invoke-WebRequest -UseBasicParsing 'https://github.com/Osmantic/ODS/archive/refs/heads/main.zip' -OutFile $odsZip
    Expand-Archive -LiteralPath $odsZip -DestinationPath $odsSrc
    $odsEntry = Join-Path $odsSrc 'ODS-main\install.ps1'
    if (-not (Test-Path -LiteralPath $odsEntry -PathType Leaf)) { throw 'The downloaded archive does not contain the ODS installer.' }
    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
    & $odsEntry
}
```

Linux и macOS: Docker должен быть установлен и запущен.

Windows: откройте **обычное окно PowerShell** (не «Запуск от имени администратора»), вставьте блок и отвечайте на запросы. Ничего предварительно устанавливать не нужно. Установщик:

1. Проверяет свободное место на диске (40 ГБ) и включена ли аппаратная виртуализация.
2. Предлагает включить WSL2 и установить Docker Desktop через winget. Windows запрашивает разрешение администратора, затем требуется **одна перезагрузка**; после повторного входа настройка продолжается автоматически.
3. Предлагает скачать Ubuntu 24.04 и запрашивает в PowerShell новое имя пользователя и пароль Ubuntu.
4. Запускает Docker Desktop и проверяет его подключение к Ubuntu. Если подключения нет, показывает единственную настройку, которую нужно включить в Docker Desktop, и продолжает, как только всё заработает.
5. Устанавливает ODS внутри Ubuntu с флагами **`--pixel --no-hermes`**. При повторном запуске флаг `--no-hermes` не используется, поэтому Hermes, добавленный из расширений, остаётся включённым. Когда Ubuntu запрашивает `[sudo]`-пароль, введите пароль Ubuntu; вводимые символы не отображаются.
6. Проверяет Pixel и Portal, затем открывает Portal в браузере и создаёт приложение **ODS** на рабочем столе и в меню «Пуск»: Portal в отдельном окне Microsoft Edge со значком ODS. Если Edge нет, вместо этого добавляет веб-ссылку **ODS Portal** на рабочий стол.

Каждый шаг спрашивает подтверждения перед изменениями и останавливается с инструкциями, если не может завершиться; после устранения проблемы перезапустите ту же команду. Резервного отката на Hermes или нативный установщик Windows нет. На машинах с NVIDIA сначала обновите драйвер Windows до версии 570 или новее. Чтобы использовать существующий дистрибутив WSL, добавьте `-Distro <имя>` (имена из вывода `wsl -l -v`).

Существующие нативные Windows-установки не переносятся и не удаляются автоматически; перед переходом см. [Windows Quickstart](ods/docs/WINDOWS-QUICKSTART.md#existing-native-windows-installations).

Если шлюз моделей ODS работает на другом устройстве, а этому ПК с Windows нужна только генерация изображений, используйте [автономный установщик ComfyUI](ods/docs/WINDOWS-COMFYUI-STANDALONE.md). Его Docker-проект и данные хранятся отдельно от полной установки ODS.

Хостинговый эндпоинт Linux/macOS проксирует текущий bootstrap-скрипт из ветки `main` репозитория. Проверенные слияния автоматически попадают туда после обновления edge-кэша. `ODS_REF` выбирает совместимую версию (checkout) репозитория. См. [Installer Trust](ods/docs/INSTALLER_TRUST.md), чтобы изучить скрипт или вручную установить аудитированный коммит; пока ни один релиз не прошёл квалификацию для верифицированного канала.

Пользователям Windows не следует выполнять команду `curl ... | bash` в PowerShell. Приведённый выше блок PowerShell скачивает публичный ZIP-архив исходников ODS и делегирует установку в Ubuntu/WSL2. Подробнее см. [Windows Quickstart](ods/docs/WINDOWS-QUICKSTART.md).

После успешного завершения установщика Portal открывается по адресу **http://localhost:3001/pixel** (установщик Windows открывает его сам и выводит точный URL). **http://localhost:3000** — это Open WebUI, отдельный интерфейс. Убедитесь, что Portal доступен, и отправьте сообщение; одна лишь загруженная панель управления ещё не доказывает готовность Pixel. Если установка не удалась или Portal работает с ограничениями, перед продолжением выполните проверки из [Windows Quickstart](ods/docs/WINDOWS-QUICKSTART.md#verify-portalpixel).

Доступ к GPU из WSL нужно проверять отдельно. Для NVIDIA требуются поддерживаемый драйвер Windows и доступ к GPU внутри WSL/Docker. На AMD настройка Windows запускает `llama-server.exe` (Vulkan) из llama.cpp через задачу ODS, привязанную к выбранной установке WSL. После подтверждения этого владения раздел **Models** («Модели») панели управления поддерживает загрузку совместимых GGUF (включая Hugging Face), активацию, изменение контекста, выгрузку и возобновление. Сервер моделей, которым установка не управляет, остаётся внешне управляемым. Установки, в которых задача ODS работала с Lemonade Server, при повторном запуске установщика переходят на llama.cpp; см. [Windows Quickstart](ods/docs/WINDOWS-QUICKSTART.md#manage-amd-models-from-portal), [руководство по WSL2 GPU](ods/docs/WINDOWS-WSL2-GPU-GUIDE.md) и [AMD GPUs now run on llama.cpp](ods/docs/MIGRATION-LEMONADE-TO-LLAMACPP.md).

Для Linux, macOS или рекомендуемой установки Windows/WSL удаление выполняется из соответствующего терминала Linux/macOS (в Windows откройте Ubuntu):

```bash
cd ~/ods
./ods-uninstall.sh --force
```

Только для **нативной установки Windows**:

```powershell
$installDir = "$env:USERPROFILE\ods"
cd $installDir
.\ods.ps1 uninstall --force
```

Примечание по восстановлению Windows: если папка среды выполнения неполна и файл `.\ods.ps1` отсутствует, выполните ту же команду из checkout исходников: `.\ods\installers\windows\ods.ps1 uninstall --force`. Перед удалением ресурсов он проверяет каталог Compose-установки контейнеров. Общее имя проекта `ods` не даёт права удалять другую установку Windows или WSL. Несвязанные тома без проверяемого владельца сохраняются, а ошибка называет соответствующий ресурс; `--force` эту проверку не обходит.

> **API-эндпоинт:** установки Linux Docker по умолчанию открывают llama-server на **http://localhost:11434** (`OLLAMA_PORT`), тогда как контейнеры используют `llama-server:8080`. Нативный Metal на macOS и `llama-server.exe` на Windows/AMD используют **http://localhost:8080**, если не задано иное; серверу Windows требуется API-ключ. Open WebUI остаётся на **http://localhost:3000**.

> **Нет GPU?** ODS также работает в облачном режиме — тот же полный стек, но на API OpenAI/Anthropic/Together вместо локального инференса:
> ```bash
> ./install.sh --cloud
> ```

> **Конфликты портов?** Каждый порт настраивается переменными окружения. Полный список см. в [`.env.example`](ods/.env.example), либо переопределите при установке:
> ```bash
> WEBUI_PORT=9090 ./install.sh
> ```

**Впервые здесь?** Прочитайте [Friendly Guide](ods/docs/HOW-ODS-SERVER-WORKS.md) или [послушайте аудиоверсию](https://open.spotify.com/episode/40MvqJ41bC8cEgvUyOyE3K) — полный рассказ о том, что такое ODS, как он работает и как сделать его своим. Техническая подготовка не требуется.

## Почему ODS?

Небольшая горстка компаний контролирует подавляющую часть мирового ИИ-трафика — а вместе с ним ваши данные, ваши расходы и ваш аптайм. Каждый запрос, который вы отправляете централизованному провайдеру, — это бизнес-информация, которой вы не владеете, работающая на инфраструктуре, которую вы не контролируете, по условиям ценообразования, которые вы не можете обсуждать.

Если ИИ становится критической инфраструктурой, его не следует арендовать. Самостоятельный хостинг локального ИИ должен быть суверенным правом человека, а не карьерным выбором.

Потому что запуск собственного ИИ не должен требовать диплома по информатике и выходных, потраченных на отладку драйверов CUDA. Сейчас настройка локального ИИ означает сшивание дюжины проектов, написание Docker-конфигураций с нуля и молитвы о том, чтобы все компоненты общались друг с другом. Большинство сдаётся и возвращается к платной подписке OpenAI.

Мы создали ODS, чтобы избавить вас от этого.

- **Одна команда** — определяет ваш GPU, выбирает подходящую модель, генерирует учётные данные, запускает всё
- **Чат с раннего старта** — режим bootstrap запускает небольшую модель, как только подняты основные сервисы, пока полная модель скачивается в фоне
- **Преднастроенные сервисы** — установка Core по умолчанию даёт локальный инференс, панель управления и чат-интерфейс (агент Portal на поддерживаемых хостах, Open WebUI в остальных случаях); добавляйте голос, рабочие процессы, поиск, RAG, генерацию изображений, наблюдаемость и инструменты разработчика из меню установщика или страницы Extensions — уже связанные между собой
- **Полностью модифицируемый** — каждый сервис является расширением. Добавьте папку, выполните `ods enable` — готово

<details>
<summary><b>Windows (PowerShell)</b></summary>

Установщик подготовит WSL2, Ubuntu и [Docker Desktop](https://www.docker.com/products/docker-desktop/), если их нет; ничего не нужно устанавливать заранее.

Откройте обычную сессию **PowerShell** (не «Запуск от имени администратора») и выполните:

```powershell
$ProgressPreference = "SilentlyContinue"
$odsSrc = Join-Path $env:TEMP ("ods-install-" + [guid]::NewGuid().ToString("N"))
$odsZip = Join-Path $odsSrc "ods-main.zip"
New-Item -ItemType Directory -Path $odsSrc | Out-Null
Invoke-WebRequest "https://github.com/Osmantic/ODS/archive/refs/heads/main.zip" -OutFile $odsZip
Expand-Archive -LiteralPath $odsZip -DestinationPath $odsSrc -Force
cd (Get-ChildItem -LiteralPath $odsSrc -Directory | Select-Object -First 1).FullName
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\install.ps1
```

> Команда `Set-ExecutionPolicy` разрешает запуск скрипта установщика в текущей сессии. Она не меняет системную политику. Запуск от имени администратора не рекомендуется, так как пути пользовательского уровня вроде `.opencode`, `data/` и `.env` могут быть созданы с правами администратора.

Эта команда ведёт подготовку WSL/Ubuntu и проверяет systemd и интеграцию Docker перед установкой Pixel. См. [Windows Quickstart](ods/docs/WINDOWS-QUICKSTART.md). Среда выполнения обычно находится в `~/ods` внутри Ubuntu; управляйте ею там через `ods status` (или `./ods-cli status` из `~/ods`). Панель Portal открывается по URL, выведенному установщиком (обычно http://localhost:3001). Нативные команды Windows `ods.ps1` не управляют этой Linux-средой.

</details>

<details>
<summary><b>macOS (Apple Silicon)</b></summary>

Требуется Apple Silicon (M1+) и [Docker Desktop](https://www.docker.com/products/docker-desktop/).
**Сначала установите Docker Desktop и убедитесь, что он запущен.**

```bash
git clone https://github.com/Osmantic/ODS.git ~/src/ODS
```

## Что входит в комплект

### Чат и инференс
- **Open WebUI** — полнофункциональный чат-интерфейс с историей бесед, веб-поиском, загрузкой документов и [30+ языками](https://docs.openwebui.com)
- **llama-server** — высокопроизводительный LLM-инференс с непрерывной батчизацией, автоматически выбирается под ваш GPU; хост-API Linux Docker по умолчанию `localhost:11434`, нативные пути macOS/Windows используют `localhost:8080`, контейнерный API работает на `8080`
- **LiteLLM** — API-шлюз с поддержкой локального/облачного/гибридного режимов
- **TEI Embeddings** — сервис текстовых эмбеддингов для RAG и поисковых процессов

### Голос
- **Whisper** — распознавание речи (речь в текст)
- **Kokoro** — синтез речи (текст в речь)

### Агенты и автоматизация
- **Portal** — встроенный основной разговорный ассистент на Apple Silicon macOS и квалифицированных хостах Ubuntu 24.04/26.04 или Debian 12 с systemd, включая квалифицированные установки WSL2 через установщик Linux. Доступ к приватному репозиторию или отдельный флаг лицензии не требуются; доступен в Dashboard и через совместимый маршрут модели Open WebUI. Нативный установщик PowerShell не устанавливает хост-среду Portal.
- **Hermes Agent** — независимый универсальный агент, доступен вместе с Portal; включает память, навыки и прокси с опциональной картой владельца для контроля доступа; по умолчанию — прямой доступ
- **n8n** — автоматизация рабочих процессов с 400+ интеграциями (Slack, почта, базы данных, API)
- **APE** — Agent Policy Engine для аудита и контроля автономных вызовов инструментов
- **OpenCode** — браузерный ИИ-ассистент для программирования, подключённый к локальному стеку
- **Memory Shepherd** — хост/systemd-хелпер для управления жизненным циклом памяти агентов

### Знания и поиск
- **Qdrant** — векторная база данных для генерации с дополненным поиском (RAG)
- **SearXNG** — самостоятельный хостинг веб-поиска (без слежки)
- **Perplexica** — движок глубоких исследований
- **Brave Search** — опциональная платная интеграция с Brave Search API

### Творчество
- **ComfyUI** — узловая (node-based) генерация изображений

### Приватность и эксплуатация
- **Privacy Shield** — прокси для очистки персональных данных (PII) при API-вызовах
- **Dashboard** — метрики GPU в реальном времени, состояние сервисов, управление моделями
- **Dashboard API** — API состояния сервисов, настройки, статуса, метрик и управления за панелью
- **Token Spy** — монитор расхода токенов для локального и проксируемого LLM-трафика
- **Langfuse** — опциональная наблюдаемость и трассировка LLM

## Автоопределение оборудования

Установщик определяет ваш GPU и сначала назначает детерминированный аппаратный уровень (tier). Затем Linux и macOS запускают версионированный селектор каталога (`ods/scripts/select-model.py`), а Windows использует селектор каталога на PowerShell в `ods/installers/windows/lib/tier-map.ps1`; оба читают `ods/config/model-library.json`, чтобы выбрать лучший устанавливаемый GGUF для обнаруженного диапазона памяти. Итоговый выбор записывается в `.env` в переменные `LLM_MODEL`, `GGUF_FILE`, `MAX_CONTEXT` и `MODEL_RECOMMENDATION_*`.

`MODEL_PROFILE=qwen` — профиль каталога по умолчанию. `MODEL_PROFILE=gemma4` принудительно использует Gemma 4 там, где она доступна, а `MODEL_PROFILE=auto` выбирает Gemma 4 на уровнях NVIDIA, AMD Strix Halo, Apple Silicon и Intel Arc. Переопределить семейство моделей можно так: `MODEL_PROFILE=gemma4 ./install.sh`. Модель можно сменить в любой момент после установки (см. [Смена моделей](#смена-моделей)).

В таблицах ниже — то, что селектор каталога выбирает сегодня для распространённого оборудования с профилем по умолчанию и нижней границей контекста 64K (`python ods/scripts/select-model.py --profile qwen --installable-only --min-context 65536 …`). Точный выбор может отличаться в зависимости от обнаруженной VRAM/RAM, архитектуры хоста и имеющихся загрузок. Измерьте скорость работы на своей машине после первого запуска.

### NVIDIA

| Память | Выбор по умолчанию | Контекст | Пример оборудования |
|--------|--------------|---------|------------------|
| 8–16 ГБ VRAM | Qwen3.5 9B (Q4_K_M) | 64K | RTX 4060, RTX 3060 12GB, RTX 4070-класс |
| 24–32 ГБ VRAM | Qwen3.5 27B (Q4_K_M) | 64K | RTX 4090, RTX 5090 |
| 48 ГБ VRAM | Qwen3.6 35B-A3B (UD-Q4_K_M) | 128K | RTX 6000 Ada, L40S |
| 96 ГБ+ VRAM (x86_64) | Qwen3 Coder Next (Q4_K_M) | 128K | RTX PRO 6000, мульти-GPU |
| 128 ГБ объединённой памяти (arm64) | Qwen3.6 35B-A3B (UD-Q4_K_M) | 128K | DGX Spark / GB10 |

### AMD Strix Halo (объединённая память)

| Память | Выбор по умолчанию | Контекст | Оборудование |
|--------|--------------|---------|----------|
| 64–128 ГБ объединённой памяти | Qwen3.6 35B-A3B (UD-Q4_K_M) | 128K | Ryzen AI MAX+ 395 |

Селектор не направляет хосты с объединённой памятью на Qwen3 Coder Next из-за задокументированных проблем корректности на этих бэкендах.

### Apple Silicon (объединённая память, Metal)

| Память | Выбор по умолчанию | Контекст | Пример оборудования |
|--------|--------------|---------|------------------|
| 8 ГБ | NVIDIA Nemotron3 Nano 4B (Q4_K_M) | 64K | M1/M2 base |
| 16–36 ГБ | Qwen3.5 9B (Q4_K_M) | 64K | M4 Mac mini, M3 Pro |
| 48 ГБ+ | Qwen3.6 35B-A3B (UD-Q4_K_M) | 128K | M4 Pro/Max, Mac Studio |

### Только CPU

| ОЗУ системы | Выбор по умолчанию | Контекст |
|------------|--------------|---------|
| 8–12 ГБ | Qwen3.5 2B (Q4_K_M) | 64K |
| 16–20 ГБ | Qwen3.5 4B (Q4_K_M) | 64K |
| 24 ГБ+ | Qwen3.5 9B (Q4_K_M) | 64K |

### Intel Arc (Linux, SYCL)

Intel Arc — экспериментальная платформа (Tier C). Автоопределение пока не распознаёт GPU Arc, поэтому укажите уровень самостоятельно: `./install.sh --tier ARC_LITE` для карт на 6–8 ГБ или `--tier ARC` для карт на 16 ГБ. См. [руководство по Intel Arc](ods/docs/INTEL-ARC-GUIDE.md).

## Режим bootstrap

ODS по умолчанию использует режим bootstrap, чтобы вы могли начать работу до завершения загрузки большой модели:

1. Установщик скачивает Qwen3.5 2B (около 1,3 ГБ) и запускает её.
2. Вы можете общаться, как только подняты основные сервисы.
3. Полная модель для вашего оборудования скачивается в фоне.
4. Когда загрузка проверена, ODS перезапускает сервер моделей на полной модели. Запросы, выполнявшиеся во время перезапуска, нужно повторить.

Модель bootstrap стартует с контекстным окном 64K, чтобы агенты работали в первой сессии. После замены ODS восстанавливает целевой размер контекста полной модели.

Пропустить bootstrap: `./install.sh --no-bootstrap`

## Смена моделей

Установщик подбирает модель под ваше оборудование, но вы можете сменить её в любой момент. Рекомендуемый способ — **Dashboard → Models**: он показывает модели, подходящие вашему оборудованию, скачивает их с проверкой контрольных сумм и загружает. Если модель не запускается, ODS возвращает предыдущую.

Из командной строки:

```bash
ods model current              # Что сейчас запущено?
```

Уже есть нужный вам GGUF? Положите единственный файл `.gguf` в `data/models/`, затем откройте Dashboard → Models и загрузите локальную запись. Для headless-обслуживания можно вместо этого задать `GGUF_FILE` и `LLM_MODEL` в `.env` и перезапустить сервер моделей:

```bash
ods restart llm
```

Ручное изменение `.env` не откатывается автоматически. Если модель не загружается, верните прежние значения и перезапустите снова.

## Расширяемость

ODS спроектирован для модификаций. Каждый сервис — это расширение: папка с `manifest.yaml` и `compose.yaml`. Панель управления, CLI, проверки работоспособности и compose-стек обнаруживают расширения автоматически.

```
extensions/services/
  my-service/
    manifest.yaml      # Метаданные: имя, порт, эндпоинт проверки здоровья, GPU-бэкенды
    compose.yaml       # Фрагмент Docker Compose (автоматически вливается в стек)
```

```bash
ods enable my-service     # Включить
ods disable my-service    # Отключить
ods list                  # Посмотреть всё
```

Сам установщик модульный — 41 библиотечный модуль, общий реестр сервисов и 14 упорядоченных файлов фаз. Хотите добавить аппаратный уровень, заменить модель по умолчанию или пропустить фазу? Начните с карты архитектуры установщика, чтобы обновить генераторы Linux, macOS, Windows, upgrade и host-agent согласованно.

[Полное руководство по расширениям](ods/docs/EXTENSIONS.md) | [Архитектура установщика](ods/docs/INSTALLER-ARCHITECTURE.md)

## ods-cli

CLI `ods` управляет всем вашим стеком:

```bash
ods status                # Проверки работоспособности + статус GPU
ods list                  # Все сервисы и их состояние
ods logs llm              # Просмотр логов (алиасы: llm, stt, tts)
ods restart [service]     # Перезапуск одного или всех сервисов
ods start / stop          # Запуск или остановка стека

ods mode cloud            # Переключение на облачные API через LiteLLM
ods mode local            # Возврат к локальному инференсу
ods mode hybrid           # Локальный — основной, облачный — резервный

ods model swap T3         # Переключение на другой аппаратный уровень
ods enable n8n            # Включить расширение
ods disable whisper       # Отключить одно

ods config show           # Просмотр .env (секреты скрыты)
ods preset save gaming    # Снимок текущей конфигурации
ods preset load gaming    # Восстановить его
```

## Сравнение с аналогами

ODS строится на инструментах, которыми вы, возможно, уже пользуетесь, а не заменяет их. Он устанавливает их, связывает между собой и даёт одно место для управления ими.

| Если вы используете… | Он даёт | ODS добавляет |
|---|---|---|
| **Ollama, llama.cpp или LM Studio** | Локальный запуск моделей | Выбор модели с учётом оборудования, окружающие сервисы и панель управления ими |
| **Open WebUI** | Чат-интерфейс с RAG, голосом и интеграциями генерации изображений | Устанавливает и настраивает его рядом с локальным инференсом, речью, поиском и сервисами изображений, управляет входом и сетевой доступностью |
| **LocalAI** | OpenAI-совместимый API с текстовыми, аудио и графическими бэкендами | Панель управления, агент Portal, рабочие процессы и каталог приложений-дополнений вокруг локального инференса |
| **Self-hosted AI starter kit n8n** | Автоматизация рабочих процессов с локальной моделью | Рабочие процессы как одна часть управляемого локального ИИ-сервера |

Собственный фокус ODS — слой вокруг этих инструментов: определение оборудования, выбор и проверка моделей, команды жизненного цикла (установка, обновление, резервное копирование, удаление) и каталог расширений.
